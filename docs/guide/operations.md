# 运行与维护

本页说明容器的进程守护、日志、健康检查、备份与升级方法，以及部署时的安全建议。

## 进程守护

入口脚本是容器的主进程，负责启动并守护以下进程：

- QQ 客户端；
- 协议端（`qqcache serve`）；
- WebUI 后端（BFF）。

具体行为如下。

- 协议端或 WebUI 后端退出后，约 10 秒内自动重新启动。
- QQ 主进程退出后，入口脚本会在十几秒内重新启动 QQ。QQ 可能自行重启，此时入口脚本会接管新的主进程，不会重复启动。
- QQ 进程仍然存在，但其无障碍窗口树已消失（渲染进程失效）并持续约 2 分钟时，入口脚本会结束该进程并重新启动。启动后的前 150 秒不做此项检测。
- 协议端的界面操作锁被同一操作持有超过 180 秒时，协议端判定为卡死并退出，入口脚本随即重新启动它。服务日志中会记录持有该锁的线程调用栈，日志内容包含「GUI 锁被同一操作占用」。

## 日志

| 位置 | 内容 | 保存情况 |
|---|---|---|
| `docker logs whiskerwind` | 入口脚本的输出，以及 QQ 客户端的标准输出 | 由 Docker 管理 |
| 容器内 `/var/log/qqcache.log` | 协议端的日志 | 容器删除后丢失 |
| 容器内 `/var/log/webui.log` | WebUI 后端的日志 | 容器删除后丢失 |
| WebUI「服务日志」页 | 协议端最近 2000 条日志 | 保存在内存中，服务重启后清空 |

- 默认输出 INFO 级别日志。设置 `QQCACHE_DEBUG` 后输出 DEBUG 级别日志。
- 查看协议端日志文件：

```bash
docker exec whiskerwind tail -n 100 /var/log/qqcache.log
```

- 通过管理接口查询最近的日志。`tail` 的最大值为 1000，`level` 为最低显示级别：

```bash
TOKEN=$(docker exec whiskerwind cat /var/lib/qqcache/access-token)
curl -s "http://127.0.0.1:5700/get_logs?access_token=$TOKEN&tail=100&level=WARNING"
```

## 健康检查

| 接口 | 用途 | 说明 |
|---|---|---|
| `get_version_info` | 确认协议端正在运行 | 不访问界面，启动后即可应答 |
| `get_status` | 确认 QQ 进程存在 | `online` 表示 QQ 进程存在，不表示已登录 |
| `get_login_state` | 确认登录状态 | 返回 `state`、`qr_expired`、`self_id`、`self_name`。未登录时，`notice` 字段包含最近一次的下线提示 |
| `/screen` | 获取整个虚拟屏幕的截图（PNG） | 需要令牌。截图可能包含聊天内容 |
| `/qr` | 获取登录二维码（PNG） | 仅在等待扫码时可用，否则返回 404 |

截图示例：

```bash
curl -s "http://127.0.0.1:5700/screen?access_token=$TOKEN" -o screen.png
```

## WebUI

WebUI 默认监听 `3000` 端口，使用 `WEBUI_PASSWORD` 登录。登录会话默认保持 7 天，可通过 `SESSION_TTL_MS` 调整。WebUI 用于监控与管理，不提供会话浏览和发送消息的功能。

| 页面 | 功能 |
|---|---|
| 运行概览 | QQ 在线状态、当日收发消息数量、运行时长、通道概况与最近事件 |
| 事件日志 | 协议端推送的 OneBot 事件，支持按类型与 QQ 号过滤，可展开查看原始 JSON |
| 通道管理 | 全部对外通道的列表与编辑：OneBot 的 HTTP 监听、反向 WebSocket 与 HTTP POST 上报，以及 Satori、automatic 服务端与 automatic 反向 WebSocket。新建、修改与删除即时生效，无需重启服务。标记为「启动参数」的通道由环境变量配置，不能在页面中修改 |
| 服务日志 | 实时查看协议端日志，支持按级别与关键词过滤 |
| 状态与设置 | 登录状态（已登录、等待扫码、状态异常、容器离线），以及容器屏幕截图 |

## 登录与掉线

- 协议端不会自动重新登录。账号被下线时（例如在其他设备登录同一账号、长时间离线或触发风控），协议端会关闭 QQ 的下线提示框，并在 WebUI 中弹出提醒。
- 重新登录时，在 WebUI「状态与设置」页扫描新的二维码。
- 掉线期间收到的消息，会在重新登录后通过未读巡检补处理。

## 备份与恢复

需要备份的目录是 `data/QQ` 与 `data/qqcache`。二者包含登录态、消息库与访问凭据，应妥善保管。备份前建议先停止容器，以免复制正在写入的数据库文件：

```bash
docker stop whiskerwind
tar -czf whiskerwind-backup-$(date +%Y%m%d).tar.gz data
docker start whiskerwind
```

恢复时，先停止容器，在部署目录中解压备份以覆盖 `data` 目录，然后重新启动容器。

## 升级

- 升级前先备份数据目录。
- 镜像固定使用经过验证的 QQ 版本（当前为 3.2.33）。升级镜像时，QQ 版本可能随之变化，界面结构也可能随之改变。升级后应确认登录状态，并验证收发消息。
- 升级的具体步骤见[快速开始](/guide/getting-started)中的「停止、启动与升级」一节。

## 安全建议

- 访问令牌、WebUI 密码以及 `transports.json` 中保存的各通道令牌，等同于账号的控制权限。通道令牌以明文保存在数据目录中，应避免明文传播，也不应提交到版本库。
- OneBot 接口默认监听 `0.0.0.0`。若只在本机使用，将 `QQCACHE_HOST` 设为 `127.0.0.1`，或通过防火墙限制访问来源。
- WebUI 默认监听 `0.0.0.0`。应使用强密码，并限制访问来源。
- Satori 与 automatic 默认监听 `0.0.0.0`，此时必须有令牌，未设置时系统会自动生成。若只在本机使用，可将监听地址改为 `127.0.0.1`，此时才可以不设置令牌。
- VNC 默认只监听 `127.0.0.1`。将 `VNC_HOST` 设为其他地址时，必须同时设置 `VNC_PASSWORD`。VNC 仅建议用于查看界面，不要在其中操作 QQ。
- `/screen` 返回的截图可能包含聊天内容，`/media` 返回的文件可能包含他人发送的图片与语音，应妥善保管。
